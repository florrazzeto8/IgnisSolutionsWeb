Enfoques técnicos

3 formas de construir la card animada. Cada una tiene trade-offs distintos.

A ⭐

Zona de scroll sticky — igual que Services (recomendado)

Un div alto (~500vh) que contiene la card sticky. El scroll se divide en 2 fases:
• Fase 1 (0%–20%): card sube desde translateY(100vh) hasta 0
• Fase 2 (20%–100%): las 3 frases animan con --local-scroll (igual al ejemplo)

Pros

  • Mismo patrón que Services — código coherente
  • Control total sobre timing de cada frase
  • Funciona en todos los browsers

Contras

  • ~100 líneas JS para manejar el scroll
B

CSS Scroll-driven animations (nativo)

Usa animation-timeline: scroll() y animation-range — sin JS para la animación. Solo CSS puro.

Pros

  • Código CSS mínimo y limpio
  • Performance nativa del browser

Contras

  • No funciona en Safari antiguo (~15% usuarios)
  • El ejemplo usa JS — hay que reescribir el approach
C

Intersection Observer + animación time-based

Cuando la card llega al top del viewport, dispara las animaciones con delay/duración (como el ejemplo original, basado en tiempo, no en scroll).

Pros

  • Más simple de implementar
  • Compatible con todos los browsers

Contras

  • NO es scroll-driven — el usuario específicamente pidió eso
  • No se puede "scrubear" hacia atrás
